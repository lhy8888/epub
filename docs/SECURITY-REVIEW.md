# 自动扫描发现的处理说明

## 2026-10-10 复审修复

针对上一轮复审的五项可复现问题及一个导航控制流问题：

- 图片的共享输入预算在实际分配前扣减，签名、MIME 或 CRC 失败也消耗额度。24 个 12 MiB 异常资源的隔离复现，累计托管分配由约 288 MiB 降至约 24 MiB；第三次 12 MiB 读取超过剩余额度后直接拒绝。
- 一次搜索按物理资源路径保留有界匹配结果，重复 spine 引用及资源别名复用扫描，同时保留阅读顺序索引、失败计数和 200 个结果限制。同一 180 万字符资源引用 64 次，累计分配由约 1.2 GiB 降至约 19.2 MiB；此数字是累计分配，不是工作集。
- 人工切分保留边界空白，并标记逻辑续段；搜索和高亮共享有界上下文，跨续段匹配但不跨真实段落。加强原回归的完整文本比较，不再删除空格后比较。
- 应用在加载状态之前获得跨进程独占会话，整个生命周期持有状态目录的锁文件句柄，防止两个旧快照互相覆盖。核心回归启动独立进程验证互斥和释放后重新获取；第二次应用启动提示使用现有窗口。
- 跨章上一页传入的段尾比例定位优先于普通块可见定位；目录/链接仍使用锚点定位。Windows 回归检查长尾段实际滚动偏移。

本地 Linux 完整编译零警告/错误，55 项核心回归通过，示例 EPUB、格式和依赖审计通过。新增 Windows 回归覆盖实际图片准备预算、跨续段高亮与长尾段向前翻页；其运行结果以本次提交的 Windows CI 为准。没有把 Linux 交叉编译描述为 Windows 运行验证。

## 扫描策略与历史记录

项目启用 CodeQL `security-and-quality` 查询集，分别扫描 C# 和 Actions。除安全漏洞外，它还会给出代码质量建议和审查提示。最新详细发现见 Security 页面与 `codeql-csharp` / `codeql-actions` 的 SARIF 产物。

CI 会拒绝 `error` 级发现与安全分值 ≥7 的高危/严重发现。其他结果仍保留在报告中供审查，不能把检查通过理解为经过独立安全审计。

## 首次扫描后的修改

- 两处缩进计算先做整数乘法再隐式转为浮点数，已直接使用浮点乘法；目录深度同时限制在 0–6，消除潜在整数溢出。
- 明确异步加载/导航 `finally` 中的条件清理与无条件结束忙碌状态，整理正文空白折叠的分支，减少误导性缩进。
- 将构造完成标记设为只读；测试的 TCP 监听器显式释放；界面测试改用误差范围比较浮点字号。
- 修正测试宿主的启动与命令行隔离，避免测试参数触发自动打开书籍。另在 Windows CI 实际启动已发布的 EXE、打开示例书并正常关闭。

## 保留并审查的提示

| 提示 | 代码中的用途与边界 |
| --- | --- |
| 外部/原生代码调用 | 唯一显式 P/Invoke 用于 Windows 标题栏暗色属性；DLL 限定从 System32 加载，参数不是书籍内容 |
| `Path.Combine` | 设置和临时测试目录的状态文件与测试目录使用固定的后续文件名；所选书籍路径只做本地路径检查与读取；EPUB 条目从不通过这里解压写盘 |
| 空 catch | 用户换书、关闭或取消任务属于预期取消；关闭时状态写入失败不弹出阻塞窗口，阅读过程中保存失败会显示状态提示 |
| 异步状态条件 | `_closed`、书籍对象和代次检查用于 await / Dispatcher 期间的窗口关闭、换书与重入；保留这些检查保护异步生命周期 |
| 强制 GC | 仅用于核心性能测量的预热清理，生产代码不调用 GC.Collect |
| 捕获所有异常 | 仅在测试程序中记录失败并返回非零退出码；生产读取路径使用限定异常类型 |
| 生成代码的赋值 | WPF SDK 生成的 `obj/.../*.g.cs`，不手工修改、不提交到仓库 |
| LINQ 写法建议 | 当前是有界集合上的明确循环，不影响 EPUB 资源限制；优化前应测量真实成本 |

这些说明只对应当前代码的具体用途。未来修改相关路径时，应重新检查数据来源、资源释放与权限，不能把此文档当成永久豁免。

## 2026-10-07 深入复审

审查基线：`3edd3256989763045a65e93b51893b8418d04242`。范围包括 ZIP/XML/图片边界、元数据、阅读顺序、全文搜索、缓存、状态写入及 WPF 的换书/导航/关闭路径。以下是代码审查与自动回归，未经过独立第三方审计。

| 发现 | 修复与验证 |
| --- | --- |
| ZIP 预检查检查注释长度，而 .NET 从末尾寻找目录签名，可能选择另一个目录 | 拒绝后续歧义签名；构造两个目录并让实际解析器选取未检查的目录进行回归 |
| ZIP64 与普通目录字段及记录位置可以不一致 | 校验一致性、完整记录边界与中央目录位置；保留合法 ZIP64 的兼容测试 |
| 仅限制声明的解压体积，压缩输入可以更大 | 为资源和实际读取同时设置独立压缩输入预算 |
| 有效 XML 内容即使 ZIP CRC 错误也会被接受 | 随分块读取计算 CRC-32，与 .NET 暴露的目录 CRC 比较；只验证实际读取的资源，不预读全书。CRC 用于发现损坏，不用于认证书籍来源 |
| XML 节点限制没有计入属性 | 属性计入 75,000 项结构预算，单元素最多 256 个属性；验证属性密集的单元素和多元素文档 |
| GIF 逻辑画布较小，但图像描述符可声明超大帧 | 先扫描帧、调色板及子块，检查每帧在画布内并拒绝截断；Windows 测试同时验证合法首帧解码 |
| 图片总输入预算在读取后判断，最后一个资源可能超出预算 | 把剩余预算传入实际读取，在分配前拒绝超额资源；回归检查不会分配完整大图片 |
| 大标题和嵌套目录标签先完整拼接再截断 | 限量获取显示标签，控制字符处理与截断不拆开代理项；资源属性设长度限制 |
| 相同 fallback 链为每个 spine 项重复遍历 | 复用解析结果，遍历时检查取消；章节上限在遍历前检查 |
| 以“第 ”开头的真实章节标题可被后续小节覆盖 | 每章只使用首个目录标题，增加重名格式回归 |
| 缓存只计算正文字符，漏算锚点、链接和元素 | 最多两章、200 万字符与 8 MiB 保守结构估算；含大量长锚点的章节可以显示但不进入额外缓存 |
| 无匹配的搜索仍为每段拼接新字符串 | 复用约 8 KiB 的栈缓冲区，只为结果生成摘要；保留跨内联匹配、Unicode、损坏章节跳过和结果上限 |
| 跨粗体/斜体的搜索可以命中，但高亮会在排版边界中断 | 按正文块匹配，再把高亮范围映射回各内联元素，保留原有样式；Windows 回归验证跨粗体的短语 |
| 取消无法中断解码器内部，快速操作可能堆积后台任务 | 打开和准备视图共用一个可取消的异步队列；搜索单独限为一项，排队请求不占用工作线程 |
| 同章切段可能再次解析未缓存的大章节 | 复用当前章节和分段索引，避免因为缓存预算而反复解析 |
| 新书失败前可能保留旧正文；Dispatcher 之后缺少再次校验 | 换书立即解除旧正文；再次检查书籍、代次和取消；主页/关闭清除界面引用；验证连续换书和读取中返回主页/关闭 |
| 合法的满额 Unicode 书签记录可能超过原来 1 MiB 的状态上限 | 用安全 Unicode 编码减少中文转义，状态上限调整到 2 MiB，支持最坏长度的 32 本书与每本 64 个书签；完整保存/重载回归 |
| 本地路径可通过重解析点指向网络或云文件 | 从根目录逐级检查，拒绝符号链接、目录联接及云占位文件；UNC/网络盘仍拒绝。此检查不抵御具有本机文件系统修改权限的并发攻击者 |

阅读图片的累计显示预算由 800 万像素降至 400 万像素，约 16 MB 的 Pbgra32 像素数据。WPF、原始数据、解码临时缓冲区及 GPU 内存另计；这不是总进程内存上限。保留 1,200 像素显示宽度与单图源尺寸限制，图片不依赖浏览器。

移除自定义快捷键和所有相关提示，增加全屏/退出全屏按钮；不干预标准文本复制、控件操作与 Windows 窗口管理。README 聚焦软件特点、界面和下载，实现细节移入 [设计与检查](ARCHITECTURE.md)。

### 本地对照测量

在同一 Linux / .NET 10.0.12 环境中，使用同一个 907,200 字符、1,800 段的原创合成章节，先解析并缓存，再预热一次无匹配搜索：

| 单次无匹配搜索 | 托管堆新增分配 |
| --- | ---: |
| 审查基线 | 1,944,136 字节 |
| 本轮修改 | 136 字节 |

固定栈缓冲区不计入托管堆分配。这只说明已缓存章节搜索的临时分配变化，不代表总进程内存降幅或全书搜索速度。旧代码对属性密集 XML、超出画布的 GIF 帧及 CRC 不一致资源的接受行为也在隔离的基线副本中复现；新代码对应测试要求拒绝。

本轮核心回归共 49 项；Windows 测试包含真实窗口、图像预算、跨排版高亮、全屏按钮、连续 12 次换书、读取中返回主页/关闭和状态恢复。Windows CI 输出工作集、私有字节和托管内存样本，不强制 GC，不使用这些数据宣称 Windows 11 真机低内存指标。

### 保留边界

- XML 仍有两次有界解析；取消不能即时终止 Windows 原生解码器内部的一次调用。未知组件漏洞不由这些限制完全消除。
- 缓存估算包括结构和字符串的保守费用，但不是 .NET 堆的精确测量。当前章节、UI、临时解析对象和图片分别占用内存。
- 状态保存在用户本机，校验和原子替换减少损坏；不承诺抵御同一用户权限下的本机恶意程序。
- 不支持固定版式、复杂 SVG、原书 CSS、嵌入字体和 DRM；过大或不规范的文件会被拒绝。
- Windows 11 真机冷启动、长期内存、滚动/DPI 与签名验收仍需人工完成。

解析器行为依据微软 [.NET 10.0.12 ZipArchive 源码](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.IO.Compression/src/System/IO/Compression/ZipArchive.cs)，CRC 属性依据 [ZipArchiveEntry 源码](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.IO.Compression/src/System/IO/Compression/ZipArchiveEntry.cs)。
